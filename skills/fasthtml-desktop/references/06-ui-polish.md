# 界面完善与视觉质检（⑥）

> 对应工作流 ⑥ 界面完善与视觉质检。⑤ 产出可运行的界面+业务后，本步骤把观感打磨到位并用机器视觉质检收口。**先编码后完善。**

## 完善流程

1. **逐页回看**：用 `启动.bat` 启动应用，逐页检查布局、视觉层级、间距、对比度、状态反馈。
2. **对照设计系统**：回看 `05-coding/ui-design.md` 的审美取向方法论（锚定主题 → 设计原则 → 两遍流程 → 克制与自我批评 → 文案写作），检查是否落入 AI 三俗默认（奶油底/近黑底荧光绿/报纸细线栏）。
3. **单变量迭代**：每次只改一个变量，保存一个版本（迭代日志）：

```
版本 1：页面结构（标题 + 表单 + 预览区 + 结果区）
版本 2：加上 CSS（内联样式，调整间距和颜色）
版本 3：加上布局（单栏→上下分栏→侧边栏，选最合适的）
版本 4：拆分组件的边界
```

4. **设计系统收敛**：全站一致性改 `layout.py` 一处（CSS 变量 + page() 壳），不逐页堆样式（参照 FastERP `web/layout.py`）。

## 机器视觉质检（唯一机器验收手段）

| 工具 | 作用 | 禁止事项 |
|------|------|---------|
| `scripts/ui_audit.py` | 反模式审计（纯 headless，13 条禁令 / AI Slop / a11y） | **禁止跳过** |
| `scripts/ui_window_verify.py` | pywebview 原生窗口视觉质检：DOM 断言 + 可选截图（无头截图自动回退 html2canvas） | HTML 结构验证通过 ≠ 界面没问题 |
| `scripts/ui_automate.py` | UI 交互自动化：点击/输入/导航/断言 | 验证按钮/表单/状态切换正确性 |

详细用法见 `references/07-quality-gate/Test/04-ui-tools.md`。质检/自动化 exit 1 即禁止发布。

## 验收标准

- 机器视觉质检通过（ui_window_verify）
- 反模式审计通过（ui_audit）
- UI 交互自动化通过（ui_automate）
- UI 行为变更已同步更新/新增测试
