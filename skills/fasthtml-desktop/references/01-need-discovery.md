# 需求澄清与首轮话术

## 必问问题清单

用户说"帮我做个桌面工具"时，按以下顺序澄清：

### 1. 这是什么工具？
- 做什么用的？（文件处理/数据管理/爬虫/系统工具/……）
- 用户需要输入什么？
- 工具输出什么？

### 2. 给谁用？
- 自己用 → 源码运行即可，打包可选
- 给别人用（零基础用户）→ **必须打包成 EXE**
- 对方电脑上可能没有 Python / Office / 浏览器

### 3. 需要什么交互？
- 表单填写、按钮点击、文件选择
- 进度展示、结果预览
- 是否需要托盘图标、菜单栏

### 4. 数据怎么存？
- 本地 SQLite 文件（Fastlite）
- 读写本地文件（Excel/CSV/TXT）
- 调用远程 API

### 5. 涉及哪些外部依赖？
- 需要网络访问吗？（爬虫、API 调用）
- 需要操作 Excel / Word 吗？
- 需要调用系统命令吗？

## 场景判断

| 用户描述 | 路由 |
|----------|------|
| "帮我查询/搜索某个系统的数据并导出" | → 01-announcement-downloader 示例（API 查询型） |
| "帮我采集分析数据，生成报表" | → 06-FastInsights 示例（数仓 + Plotly + 文本转 SQL） |
| "我要一套带登录的业务后台（CRM / ERP / HR / 教务 / 邮件 / 会议…）" | → 03~06、13~15 示例（多页面 + 共享认证 + SQLite 播种） |
| "帮我定时执行某个任务/监控" | → 参考 01-announcement-downloader 的 `scheduler.py` |
| 与上述都不匹配 | → 从空白骨架开始，在 app.py 中写业务逻辑 |

## 零基础用户沟通规范

如果用户说"我不懂编程"、"你帮我弄"：

1. **不要解释技术细节**。不要提 FastHTML、pywebview、uvicorn
2. **用比喻说明**："我会给你生成一个窗口软件，双击就能用"
3. **只问业务问题**："处理什么文件？输入是什么？结果长什么样？"
4. **用户的角色是提需求，AI 负责全部技术实现**

### 沟通示例

> 用户：帮我做个工具，把一堆 Excel 文件合并成一个。
>
> AI（正确）：明白了。这些 Excel 文件格式一样吗？合并后需要保留哪些列？生成的桌面工具是您自己用还是给别人用？
>
> AI（错误）：好的，我会用 pandas 读取 Excel，然后用 FastHTML 做前端界面，pywebview 包装成桌面窗口……（无用技术解释）

## 需求优先级排序（MoSCoW）

需求澄清后，按以下维度对功能进行优先级排序：

| 优先级 | 含义 | 处理方式 |
|--------|------|---------|
| **Must-have** | 必须有的核心功能 | 第一轮实现 |
| **Should-have** | 重要但可以推迟 | 第二轮实现 |
| **Could-have** | 锦上添花 | 有时间再做 |
| **Won't-have** | 本次不做 | 明确告知用户 |

产出：MVP 功能清单 = 所有 Must-have 功能。

## 确认清单

需求澄清后，向用户确认以下内容：

- [ ] 工具用途已明确
- [ ] 输入数据格式已明确
- [ ] 输出结果格式已明确
- [ ] 用户群体已明确（自己用 / 给别人用）
- [ ] 是否需要 EXE 打包
- [ ] MVP 功能清单已确定（Must-have 项已确认）
