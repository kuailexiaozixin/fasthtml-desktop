## 十六、非功能设计

### 性能

| 场景 | 目标 | 实现策略 |
|------|------|---------|
| 页面加载 | < 500ms | 内联 CSS/JS，避免外部请求 |
| 表单提交反馈 | < 1s | HTMX 局部更新，不整页刷新 |
| 大数据量操作 | > 3s 用 SSE | 后台线程处理 + SSE 进度推送 |
| SQLite 查询 | < 100ms | 根据读写路径加索引 |

> fasthtml-desktop 是本地应用，没有网络延迟和并发压力。
> 性能问题通常不是架构问题，而是**没加索引**或**做了不必要的同步等待**。

### 安全

| 关注点 | 策略 |
|--------|------|
| 用户文件 | 不自动读取用户文件，由用户显式选择（pywebview 文件对话框） |
| API Key | 通过环境变量或 config.json 传入，不硬编码 |
| 日志脱敏 | 日志中不记录用户文件路径和敏感参数 |
| 路径穿越 | 所有文件操作限制在用户指定的目录内 |

### 可观测性

```python
import logging

# 三层日志：每层有不同的日志关注点
# 路由层：记录请求路径和耗时
logger.debug(f"路由 /process 被调用")

# 服务层：记录业务操作结果
logger.info(f"处理完成：{count} 条记录")

# 数据层：只记录异常
logger.warning(f"查询超时，建议检查索引是否缺失")
```

| 层级 | 日志级别 | 记录内容 |
|------|---------|---------|
| 路由层 | DEBUG | 请求路径、参数（脱敏）、耗时 |
| 服务层 | INFO | 业务操作结果、处理量 |
| 数据层 | WARNING/ERROR | 查询失败、连接异常 |
