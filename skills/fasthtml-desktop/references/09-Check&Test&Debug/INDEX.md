# 质量体系（Check & Test & Debug）

质量相关主题按 **Check / Test / Debug** 三层组织，明确边界、高内聚低耦合：

- **`Check/`** —— 静态关卡（不运行完整应用）：语法 / 导入 / Ruff / UI 禁令 / 路由与链路校验。写入/改动后立即执行。
- **`Test/`** —— 动态验证（运行真实代码路径）：TDD（单元/集成/数据驱动）→ E2E → 冒烟 → UI 工具用法。编码完成后执行。
- **`Debug/`** —— 失败处理闭环（复现 → 定位 → 修复 → 回归 → 沉淀）。任何 Check/Test 失败后进入。

## 入口

| 层级 | 目录 | 覆盖内容 |
|------|------|----------|
| 静态关卡 | [`Check/INDEX.md`](Check/INDEX.md) | 语法检查、UI 反模式审计、路由卫生与链路校验 |
| 动态验证 | [`Test/INDEX.md`](Test/INDEX.md) | TDD 核心、E2E、冒烟与交付门禁、UI 工具用法 |
| 失败处理 | [`Debug/INDEX.md`](Debug/INDEX.md) | 调试纪律（Prove-It、flaky、干净复测）、排障沉淀 |

## 核心心智

```
写代码 → Check（静态关卡，不过不让跑）
       → Test（动态验证：TDD/E2E/冒烟/工具）
       → 失败 → Debug（复现→定位→修复→回归→沉淀）
       → 全绿 → 发布门禁（release_gate）→ 打包
```

- **Check 管「规约对不对」**：静态、快、不运行完整应用。
- **Test 管「行为对不对」**：动态、运行真实代码路径。
- **Debug 管「失败为什么、怎么修」**：不是门禁，是失败后的处理闭环。

详细拆分映射、编号规则与引用变更见 `../../docs/troubleshooting.md` 相关章节及仓库 `plan/` 下的重组方案。
